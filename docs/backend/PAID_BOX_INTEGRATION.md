# Internal paid-box integration — November 4

This is sandbox-only implementation work on `codex/box-products`, published as Android version 3 on Google Play internal testing; phone purchase acceptance remains unverified. All 13 Google products and their RevenueCat offering mappings are now verified. The server sandbox policy is enabled for internal phone testing; production grants remain rejected. Never install this v5-save build before the legacy-backup migration accepts version 5.

The runtime disables optional SDK diagnostics and automatic device-identifier collection.

The pinned RevenueCat Unity SDK is 10.0.0 via OpenUPM with Unity's official dependency manager 2.1.1. `Packages/manifest.json` changes are required for checkout. The approved opaque Pip icon is imported unchanged and applied by an editor build preprocessor. the approved full artwork is fitted into the 72dp viewport of Android’s 108dp adaptive background, with a transparent foreground; no opaque composite is placed in the foreground. The generated fallback PNG is resized from the approved master, replacing Unity’s logo.

`PaidBoxCheckoutService` binds Claude's existing HUD events/contracts without modifying any HUD files. It configures RevenueCat only with the authenticated Apple/Google account UUID, matches the approved offering/package/product identities, uses native localized price strings, requests server odds, and requests recovery after payment. No SDK success flag grants a toy. Offline/failed server status preserves the non-purchasable Coming soon lineup.

`pockle-paid-boxes` verifies Auth and the current SQL session, reads the account's non-subscription transactions from RevenueCat, rejects mismatched original account IDs and every non-sandbox/promotional transaction, and passes only verified purchase fields into a service-only SQL function. A unique `(store,environment,transaction_id)` fixes all 1/3/5 child outcomes once, in one database transaction. Replay returns that receipt. The local v5 save retains an additive receipt-ID list, preventing a repeated recovery from adding copies twice; a failed persistence cannot notify observers or reveal. A pre-v5 JSON backup is retained. Existing legacy inventory/fusions remain separate from server-earned copies; they do not acquire fabricated edition numbers.

Reveal progress is persisted locally and retried to the server; server progress only moves forward. On restart the same saved outcomes resume. Ambiguous payment failures remain pending rather than automatically retrying a charge. Sandbox copies have no production edition serials. Production edition allocation/stock reservations, refunds/revocation, authoritative fusion/trading integration, and the complete production purchase acceptance remain outstanding. Do not advertise this slice as launch-ready payments.

## Odds in this test

Wally starts 88% Common, 8% Rare, 3% Epic, 1% Secret. Every finish within a tier is equally likely. Collections lacking Rare/Epic return those weights to Common (99% Common / 1% Secret for the ten-finish collections). Mystery Mix selects uniformly among the eleven active collections for each child. These exact effective odds come from SQL and are displayed before purchase. No completion boost or real remaining-edition quantity is claimed. This sandbox policy is separate from the production stock-reservation design.
